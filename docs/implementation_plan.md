# StuTrade Web 实施方案

本文记录前端尚未完成的页面、交互、依赖和验收。当前实现以代码、测试和根 README 为准；产品成交语义以 StuTrade 主仓库文档为准。

## 当前基线

应用壳层、桌面与移动导航结构、核心路由、会话 Provider、React Query、OpenAPI 生成和基础测试已建立。市集、详情、出售/求购发布、我的发布、主动购买、主动接单、订单与线下履约确认已连接确定性 MSW 协议夹具；撮合仍是占位骨架，所有业务页面尚未连接真实后端。MSW 只为界面开发和测试返回预设 HTTP 响应，不验证或模拟宿主业务规则。

## 数据与交互计划

- 以 OpenAPI 生成类型实现统一 HTTP 客户端和边界错误转换。
- 浏览市集和详情允许匿名访问；写操作依赖同源 HttpOnly 会话 Cookie。
- 价格按最小货币单位传输并格式化为人民币，不使用浮点计算。
- 列表使用契约定义的 cursor 分页，空结果始终渲染为空数组状态。
- 409 冲突、401 未登录、403 无权限和资源失效使用不同反馈。
- 发布、确认和成交 mutation 成功后只失效相关查询，不维护平行本地业务状态机。

## 验收目标

- 两名用户可以完成自动撮合、卖方接单和买方购买三条路径。
- 自动撮合必须双方确认；主动成交不要求第二次确认。
- 重复确认不会在界面上产生重复订单。
- 两人争抢同一挂单时，失败方看到明确冲突并刷新资源状态。
- 375 px 手机视口和桌面视口没有溢出、遮挡或不可操作控件。
- 键盘焦点可见，颜色对比可读，减少动效设置得到尊重。
- 三条路径均有真实浏览器 E2E 覆盖，并通过 `bun run check`。
