# StuTrade Web 组件说明

## 组件定位

StuTrade Web 是校园二手书交易的浏览器客户端。首页直接进入可操作的市集，不设置营销落地页；核心导航为市集、发布、撮合、订单和我的。

前端独立构建和部署，只通过业务宿主的 `/api/v1` 协作。它负责页面、交互、可访问性、客户端请求状态和静态产物，不拥有成交规则、持久化或后端状态转换。

## 信息结构

```text
StuTrade
|-- 市集
|   |-- 在售书籍
|   `-- 求购需求
|-- 发布
|-- 撮合
|-- 订单
`-- 我的
```

当前路由已为市集、发布、撮合、订单、个人、登录和注册提供稳定入口。桌面端使用顶部导航，移动端使用底部导航；详情和完整业务状态将在对应纵切中实现。

## 设计方向

目标用户是在手机上快速找教材、比价和完成面交的学生。界面优先呈现书籍、价格、成色和交易状态，不采用营销页或通用 SaaS 仪表盘布局。

当前设计 token 为：

| 名称 | 色值 | 用途 |
| --- | --- | --- |
| Paper | `#F6F8F7` | 页面背景 |
| Ink | `#17201B` | 主要文本 |
| Campus green | `#176B4D` | 主操作与成功状态 |
| Information blue | `#315DA8` | 求购与信息状态 |
| Alert red | `#C44137` | 失败与危险操作 |
| Divider | `#D8DEDA` | 分隔线与控件边界 |

书籍和交易信息是主要视觉信号。界面不使用装饰性渐变、无意义标签或层层嵌套卡片；动效只反馈用户操作，并尊重 `prefers-reduced-motion`。

## 技术边界

- React Router 拥有浏览器路由。
- React Query 管理远端请求状态；局部交互状态保留在组件附近。
- 应用级 session provider 管理当前身份，不在浏览器持久化 bearer token。
- MSW 在开发和测试中模拟相同 HTTP 结构。
- `openapi/stu-trade.yaml` 生成 `src/api/generated/schema.ts`，生成文件不得手工修改。
- `bun run check` 统一执行 OpenAPI lint、生成同步检查、代码 lint、测试和构建。

## 契约边界

本仓库 OpenAPI 是 `/api/v1` 路径、DTO、状态码和错误结构的权威来源。StuTrade 主仓库拥有产品语义；后端评审并实现固定版本的结构契约。

前端只展示后端返回的状态和错误，不重新实现 ISBN 匹配、自买限制、挂单有效性、确认幂等或同一挂单只能成交一次等宿主规则。
